# CONTENTRIUM Keys 설치·복구 안내

대상: **2.0.0-preview.10**, Windows x64, 두벌식 한글. Windows ARM64·32비트 운영체제와 관리 정책으로 설치가 금지된 PC는 지원 대상으로 검증하지 않았습니다. 별도의 .NET 런타임은 필요하지 않습니다.

## 다운로드와 사전 준비

[공식 설치 파일](https://github.com/contentriumkorea/rium-keys/releases/download/v2.0.0-preview.10/CONTENTRIUM-Keys-Setup.exe)을 받습니다. `Source code.zip`은 설치 파일이 아닙니다. GitHub의 `Latest`가 구형 1.1.1을 가리킬 수 있으므로 이 링크의 **preview.10**을 확인하세요.

아직 코드 서명이 없는 Preview이므로 Windows에 게시자를 확인할 수 없다는 표시가 나올 수 있습니다. 배포 페이지의 `SHA256SUMS.txt`와 파일 SHA-256을 대조할 수 있습니다. 조직의 보안 정책을 변경해서 설치하지 마세요.

1. 한국어 언어 팩과 Microsoft 입력기가 있어야 합니다. 새 설치 전에는 한국어 Microsoft 입력기를 선택합니다. 입력기 이름 없이 단순 영문 키보드만 활성화된 구성은 이 Preview 설치기가 복구 상태를 정확히 저장할 수 없어 중단할 수 있습니다.
2. 처음 설치할 때 기본 입력 방법도 한국어 Microsoft 입력기로 설정되어 있어야 합니다. 위치: Windows 설정 → 시간 및 언어 → 입력 → 고급 키보드 설정 → 기본 입력 방법 재설정. Microsoft 입력기를 삭제하지 않습니다.
3. 작업 문서를 저장하고 편집 프로그램을 종료합니다. 설치기가 작업 앱을 강제로 닫지는 않습니다. 실행 중인 앱은 이전 DLL을 계속 사용하므로 설치 뒤 재실행해야 합니다.
4. Setup은 설치할 사용자 계정에서 일반 실행합니다. 관리자 권한 실행 메뉴를 사용하지 마세요. 입력기 등록 단계에서만 Windows 관리자 확인을 요청합니다.

## 실제 설치 순서

1. `CONTENTRIUM-Keys-Setup.exe` → 다음 → 포함된 MIT 라이선스 확인 → 설치.
2. Windows 관리자 확인창에서 **예**를 누릅니다.
3. **CONTENTRIUM Keys - 입력 확인** 창이 열리면 입력칸을 클릭합니다.
4. 한/영 키를 누르지 말고 **G K S R M F → Space**를 눌러 `한글 `을 만듭니다. 복사·붙여넣기는 입력기 검증이 되지 않습니다.
5. **단축키 확인 (V)** 버튼을 클릭한 다음 **키보드 V**를 누릅니다. 버튼을 클릭하는 것만으로는 통과하지 않습니다.
6. 입력칸의 글자 끝을 클릭하고 **G K S R M F → Space**를 한 번 더 입력합니다. 앞의 글자를 지우지 않습니다.
7. `한글 한글 `이 되면 시험 창이 자동으로 닫힙니다. 설치 완료 화면까지 기다린 다음 마침을 누릅니다. 시험은 약 6분 안에 진행해야 합니다.
8. 작업 프로그램을 다시 실행합니다. Windows + Space로 **CONTENTRIUM Keys**를 선택합니다.

표시: **가 = 한글**, **A = 영어/직접 입력**, **CK = 입력기 선택**. 우클릭 ‘입력기 사용’의 체크를 해제하면 직접 입력합니다. 별도 설정 앱이나 자동 실행 EXE는 없습니다. Windows가 기본 입력기로 선택된 프로필을 로그인 후 불러옵니다.

## 버전별 경로

| 기존 설치 | 진행 |
| --- | --- |
| 없음 / RIUM Keys 1.1.1 트레이 유틸리티 | 새 설치. 입력 확인 통과 후 기존 유틸리티 제거 |
| native preview.9 | 같은 EXE에서 preview.10으로 업데이트 |
| native preview.2–8 등 다른 Preview | 설치된 앱에서 기존 입력기 제거 → 이 설치 파일 실행 |
| native preview.10 | 같은 사용자 설치 상태·파일·등록을 검사. 정상이면 중복 설치 생략 |

기존 Preview는 저장된 복구 정보가 있어야 업데이트/제거할 수 있습니다. 다른 사용자 계정에서 설치했거나 복구 기록이 없으면 강제로 덮어쓰지 않고 중단합니다.

## 문제가 있을 때

- **관리자 확인을 취소함:** 설치가 완료되지 않습니다. 기존 등록 확인이 끝난 뒤 설치 파일을 다시 실행합니다.
- **입력 확인 실패 / 닫음 / 시간 초과:** 새 입력기를 정상 설치로 확정하지 않습니다. 업데이트는 이전 COM 경로와 이름·아이콘을 복구합니다. 새 설치는 등록을 정리하고 이전 입력 상태로 복구를 시도합니다. 화면에 성공 메시지가 없는 상태를 완료로 간주하지 마세요.
- **다시 실행했더니 기존 폴더나 복구 상태 오류:** 이전 시도 파일을 보존하기 위해 중단한 것입니다. DLL이나 레지스트리를 직접 삭제하지 말고 아래 로그와 상태를 확인하세요. 같은 버전의 실패한 설치 폴더를 자동으로 지우거나 덮어쓰지 않습니다.
- **옛 K/CK가 계속 표시됨:** 먼저 해당 앱을 완전히 다시 실행하세요. Windows 입력기 선택 표시가 예전 아이콘을 캐시한 경우 로그아웃·로그인으로 갱신됩니다.
- **단축키가 안 됨:** 현재 입력기가 CONTENTRIUM Keys인지 확인합니다. 지원이 확인되지 않은 프로그램·버전·입력 영역일 수 있습니다. 프로그램 이름과 버전, 입력칸→단축키 영역 전환 순서를 함께 기록하면 재현에 도움이 됩니다.

설치 로그: `%LOCALAPPDATA%\Contentrium\KeysSetup`

복구 기록: `%LOCALAPPDATA%\Contentrium\RIUM Keys\Recovery`

설치 폴더: `C:\Program Files\RIUM Keys\2.0.0-preview.10` — 이름 변경 전 경로를 유지해 기존 입력기와 연결합니다.

제거: Windows 설정 → 앱 → 설치된 앱 → **CONTENTRIUM Keys → 제거**. 이전 입력기로 되돌린 다음 등록을 제거합니다. 이미 실행 중인 앱에 로드된 DLL은 당장 삭제되지 않을 수 있습니다. 개인 설정·복구 기록은 보존합니다.

## 검증 범위

자동 검사는 패키지 무결성, x64/x86 입력 엔진·상태 아이콘, 설치 스크립트의 경로·기존 파일 보존·아이콘 복구를 다룹니다. 실제 설치 검사는 이 PC의 preview.9 → preview.10 업데이트 경로와 별도 입력 확인 창을 대상으로 기록합니다. 새 Windows 환경 전체나 모든 앱 호환성을 통과했다는 의미는 아닙니다. 실행 결과와 날짜는 [배포 기록](preview-10-release.md)을 확인하세요.
